Use **Super Admin → Institution Settings → Test Data Cleanup**. Scan is read-only. The purge requires the scan fingerprint, typed confirmation, and a dedicated 32-byte hex secret in `TEST_DATA_BACKUP_KEY`. Keep this key in the deployment secret store and retain it for recovery. Never add it to Git or send it through the browser.

Production records without reviewed provenance are protected by default. The operator-only `server/scripts/review-test-provenance.mjs` accepts an EJSON manifest of exact `collection` and `recordId` pairs. Run it with `--inspect manifest.ejson` against the intended database to obtain record hashes. After checking independent evidence that every record is test-only, add each exact `digest` and a short `evidence` statement. Run `--register manifest.ejson` with `CONFIRM_TEST_PROVENANCE=REVIEWED`. Registration makes no deletions. Names, test email domains, and local fixture labels never authorize a production purge. Re-review records whose contents changed.

Before a production handover purge, pause writes affecting the reviewed records, verify the database backup, and ensure test faculty are already inactive in MongoDB and disabled in Firebase. Scan again. The system refuses student identities, institutional configuration, unknown references and shared history. Explicitly test-only academic records must all be reviewed, including dependent enrollment and workflow rows. The purge saves and verifies an encrypted backup and writes a MongoDB journal in the same transaction as the deletions. Firebase removal follows the commit; resume it from the cleanup panel if interrupted. The backup stores MongoDB records, not Firebase passwords. The backup format is EJSON encrypted with AES-256-GCM: decode the stored base64 data, IV and authentication tag and decrypt with the retained deployment key. Keep access to backups operator-only.
